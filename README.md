# 偽装スペックチェッカー (but-what-if-fake-device)

格安Androidタブレットなどでときどき見かける「RAM 16GB（実は4GB）」「ストレージ 1TB（実は64GB）」「Android 14（実はAndroid 10）」といった **スペック偽装** を、端末上で確認するためのAndroidアプリです。

偽装ROMは「設定」アプリの表示や `build.prop` を書き換えていることが多いので、このアプリでは **カーネルの値・フレームワーク実体・実測** を突き合わせて矛盾がないかを調べます。

## チェック項目

| 区分 | 内容 | 主な検出方法 |
|---|---|---|
| RAM | 物理RAM容量 | `/proc/meminfo` と Android API の値を比較。仮想RAM（スワップ / RAM拡張）を分けて表示 |
| RAM（実測） | 実際に使えるRAM | 別プロセスで共有メモリにランダムデータを書き込み、物理RAMが埋まるまで確保して推定 |
| ストレージ | 公称容量 | 設定アプリの表示値・`/data` の実サイズ・カーネルのブロックデバイス容量を比較 |
| ストレージ（実測） | 実際に保存できる容量 | H2testw / F3 と同じ方式。空き容量に位置ごとに異なるデータを書き込み、すべて読み戻して照合 |
| ディスプレイ | 解像度・リフレッシュレート・HDR・広色域 | ディスプレイモード一覧、dpi値からの画面サイズ計算 |
| ディスプレイ（実測） | 実リフレッシュレート | Choreographer のフレーム間隔を3秒間計測 |
| ディスプレイ（目視） | 実パネル解像度・階調・ドット抜け | 1px縞模様 / 市松模様、グラデーション、単色、マルチタッチ同時数 |
| CPU / SoC / GPU | SoC名・コア構成・GPU | `/proc/cpuinfo` のCPU part番号から実コア種別を特定。SoC名とGPUの組み合わせ（例: Snapdragonなのに非Adreno）を検証 |
| OS | Androidバージョン | 表示バージョンとAPIレベルの整合性、フレームワーク実体が持つバージョンコード、APIレベル固有クラスの存在確認 |
| 端末情報 | 型番・メーカー名の書き換え | `ro.product.*` を system / vendor / odm などパーティション別に比較 |
| カメラ | 画素数 | センサー画素数と最大出力サイズを比較し、補間による画素数水増しを検出 |
| バッテリー | 容量 | 設計容量（電力プロファイル / カーネル）と、残電荷から推定した満充電容量を比較 |
| 機能 / センサー | GPS・NFC・ジャイロなど | 仕様表との突き合わせ用に一覧表示 |
| Shizuku連携（任意） | shell権限でしか読めない情報 | 物理ストレージ容量、zramのストレージ書き出し（RAM拡張）、`dumpsys meminfo` / `wm size` / `dumpsys display`、カーネルのバッテリー容量、CPU最大クロック |

結果は「OK / 注意 / 疑い / 情報」で表示し、「結果を共有」でテキストレポートとして書き出せます。

表示言語は日本語と英語に対応しています。端末の言語が日本語なら日本語、それ以外は英語で表示します（Android 13 以降は「設定 → アプリ → アプリの言語」で個別に切り替えられます）。文字列は `app/src/main/res/values/strings.xml`（英語）と `values-ja/strings.xml`（日本語）にあります。

## インストール

[Releases ページ](https://github.com/AndroPlus-org/but-what-if-fake-device/releases) の最新リリースを開き、Assets から `FakeDeviceChecker.apk` をダウンロードしてインストールしてください。

Android 7.0（API 24）以上に対応しています。Android の権限は要求しません（Shizuku連携を使う場合だけ、Shizuku アプリ上で許可を求めます）。

### Shizuku連携（任意）

[Shizuku](https://shizuku.rikka.app/) をワイヤレスデバッグまたは root で起動しておくと、「Shizuku連携」ボタンで shell 権限の追加チェックを実行できます。一度許可すれば、次回以降は起動時に自動で実行します。

- 新しい Android で通常アプリから読めない物理ストレージ容量を読み、公称容量と比較します
- zram がストレージに書き出している量（一部の「RAM拡張」）を表示し、RAM実測テストでその分を差し引きます
- `dumpsys meminfo` の総RAM、`wm size` の物理画面サイズを、アプリ向けの値と突き合わせます

shell 権限でも SELinux で読めない項目は「読み取り不可」と表示します。カーネル自体が偽装している場合は shell 権限でも見抜けません。

## 実測テストの注意

- **RAM実測テスト**: メモリを使い切るため、他のアプリが終了されることがあります。端末を再起動した直後に実行すると精度が上がります。
- **ストレージ実書き込みテスト**: アプリ専用フォルダに書き込み、終了後に削除します。既存データは消えません。容量偽装を確実に見つけるには「空き容量すべて」で実行してください（時間がかかります）。中止すると、それまでに書いた分だけ照合します。
- **ディスプレイ表示テスト**: 1px の縞模様をスマホのカメラ等で拡大して見てください。縞がきれいに分離せずグレー一色やモアレになる場合、実際のパネル解像度は申告より低い可能性があります。

## 判定の限界

- ここでの判定はヒューリスティックです。「疑い」が出ても偽装と断定はできず、逆にカーネルやHALまで改造された端末は見抜けない場合があります。
- OEM品の再ブランドでは、パーティション間で型番が違うのが正常なこともあります。
- 新しいAndroidでは `/sys/block` などが読めず、一部の項目が「読み取り不可」になります。

## ビルド

```sh
./gradlew assembleRelease
```

Android SDK（compileSdk 35）と JDK 17 以上が必要です。外部ライブラリは使っていません（Kotlin標準ライブラリのみ）。
